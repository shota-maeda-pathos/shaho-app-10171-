# 段階7（届出・承認の横断機能）の方針

2026-10-30 ユーザー承認済み（「推奨どおり進めて」）。

## 前提（調査結果）

- 届出は3か所にある：従業員の下 `employees/{id}/filings`（3軸の状態）、`santeiRuns/{id}/filings`・`bonusRuns/{id}/filings`（`status` 1本）。後の2つは届出一覧・承認一覧に出ない。
- 旧 `filingList` は在籍中の従業員を1人ずつ読むため遅く、退職者の届出が出ない。
- 模擬申請は即時に完了／失敗の2値、受付番号はランダム。送信取消・エラーのシミュレーション・承認取消はない。
- 承認一覧に一括承認・差分・期限がない。Cloud Storage は未使用。

## 方針

- 会社の下に届出の索引 `companies/{c}/filingIndex/{source}_{親ID}_{届出ID}` を置く。3か所の届出の書き込みを Firestore のトリガー（asia-northeast1）が受けて索引を更新する。既存の届出は移行の関数で入れる（本番書き込み・要確認）。
- 画面はカタログの状態名（下書き→承認待ち→承認済み→送信済み→受付済み→処理中→完了／差戻し・返戻・取消）。紙の提出は別の状態として持つ。
- 届出の期限は種類ごとにサーバーで計算し、期限が行政機関の休日（土日・祝日・12月29日〜1月3日）にあたれば翌開庁日に延ばす。

## 順番

1. 7-1 届出の横断一覧（算定・賞与を含む。従業員・種類・期間・状態・受付番号で検索、期限超過の印、今週期限）
2. 7-2 模擬申請の段階遷移（待ち時間の設定・手動で進める）、受付番号 `MOCK-YYYYMMDD-0001`、エラーのシミュレーション4種とリトライ、送信取消、模擬の返戻、紙の提出記録（提出先・方法・決定通知）、`window.confirm` を画面内の確認に。手続きは「完了」で次へ進む
3. 7-3 承認：横断の承認一覧（届出を含む）・並べ替え・絞り込み・期限優先・件数、一括承認（要点の一覧・監査ログ）、前回の版との差分、承認取消（確定した等級・免除も戻す。その等級で計算済みなら取り消さない）、放置の強調・期限超過の通知、承認時のハッシュで改ざん検知
4. 7-4 ⑥賞与不支給報告書（公式様式の取得は許可を得てから）
5. 7-5 ⑩訂正届・取消届（差分の自動検出、訂正箇所の一覧ページ。台帳・等級は自動で直さず案内する）
6. 7-6 添付書類（種類ごとのチェックリスト、関数経由で Cloud Storage に保存）
7. 7-7 PDFの保存原本（承認時点の内容と様式の版から作り直す）とZIP一括ダウンロード
8. 12種すべてを作成から提出記録まで画面で通し、チェックリストを埋める

一括作成は一括型の業務（入社・算定基礎届・賞与）で対応済みのため、横断画面には作らない。
