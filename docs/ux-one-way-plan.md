# 初心者向け「一本道」UI改善案

作成：2026-10-29。機能は概ね揃っている前提で、画面のつながりと見た目を改善する。

## 現状の問題（コードから確認）

1. **入口が多すぎる。** 同じ業務に、サイドバーの「手続き」「定例業務」「従業員台帳」「届出・帳票」や、URL直打ちでしか行けない旧画面（`/salary`・`/premium/*`・`/santei`）から入れる。初心者はどこから始めればよいか分からない。
2. **案件画面がチェックリストにとどまっている。** `procedure-detail` はステップを並べるだけで、操作するたびに別画面へ移動する（従業員詳細は1,153行・8タブ、届出一覧など）。移動先の画面は案件のことを知らないため、「手続きに戻る」「次にやること」の案内がない。
3. **手続き開始画面がプルダウン式の振り分けしかしていない。** 業務を選ぶと既存画面へ転送するだけ。入社は `/employees/new` に飛ぶが、このルートは定義されておらず `:id` = `new` として従業員詳細が流用されている。
4. **ステップ名が専門用語。** 「届出データ作成」「模擬電子申請」「紙提出記録」「完了確認」「待機中」など。ステップの目的・法定期限・次に何が起きるかの説明がない。模擬申請と紙提出が並んでいて、どちらをやればよいか分からない。
5. **ホームが「数字」中心で「やること」中心になっていない。** 統計カード、業務アラート、進行中の手続き、タスクが分散しており、優先順位（期限切れ→今週期限→差戻し→承認待ち）が分からない。
6. **見た目の統一感がない。** インラインstyle、色の直書き、状態色の不統一。ログイン画面でラベルが入力欄の枠と重なっている。ブラウザのタブ名が「Src」。

## 改善の方針

- **1つの手続き＝1つの画面で最後まで進める（ウィザード化）。** 案件画面の右側に、現在のステップの入力フォームを埋め込む。既存画面のフォーム部分を部品（コンポーネント）として切り出し、案件画面から呼び出す。別画面へ移動させない。
- **各ステップに「やること」「なぜ必要か」「次に何が起きるか」を1行ずつ表示する。** ステップ名は動詞で書く（例：「資格取得届を作る」「別の担当者が確認」）。
- **他人待ちのステップは「待ち」として明示し、ホームへ戻す。** 承認されたら通知から「続きから」で戻れるようにする。
- **ホームは「やることリスト」1本にする。** 期限順に並べ、各行に「続きから」ボタンを置く。統計は集計画面へ移す。
- **開始画面はライフイベントのカードにする。** 言葉は平易に：「人が入社する」「人が退職する」「家族が増えた・減った」「産休・育休に入る／戻る」「給料が大きく変わった」「毎月の保険料処理」「年1回の算定基礎届（7月）」「賞与を払った」。
- **毎月の処理も同じウィザードにする。** 対象月を選ぶ → 給与を取り込む → 給与の確認を依頼 → 保険料を計算 → 保険料の確認を依頼 → 明細を公開 → 徴収を記録。
- **サイドバーを5項目に減らす。** ホーム（やること）／手続きを始める／毎月の処理／従業員／承認。届出一覧・集計・試算・設定は「その他」にまとめる。
- **模擬申請と紙提出は「提出方法を選ぶ」1ステップにまとめる。** 選んだ方法の操作だけを表示する。
- **用語集とヘルプ吹き出しを用意する。** 「資格取得届とは」「標準報酬月額とは」などを、用語の横の「?」から確認できるようにする。

## 大人数の企業への対応（個別と一括の両立）

カタログ自体が一括処理を求めている：従業員CSV取込、給与CSV取込、月次保険料の一括計算と個別保留、算定対象者の自動抽出、届出の一括作成（チェックボックス）、一括承認、ZIP一括ダウンロード、複数人様式の2枚目以降の自動生成。

### 手続きの2つの型

| 型 | 対象 | 画面の形 |
|---|---|---|
| 個人型 | 入社・退職・扶養・休業・随時改定・年齢到達 | 1人分のウィザード（前述） |
| 一括型 | 毎月の処理・算定基礎届・賞与 | ステップは同じウィザードだが、各ステップの本体が「対象者一覧」になる |

### 一括型ステップの共通部品「対象者一覧」

- 全員の状態を1行ずつ表示する（例：給与 承認済み／保険料 未計算／保留中）。
- 既定の表示は「要対応の人だけ」。問題のない人は件数だけ表示する（例：「482名 問題なし」）。
- 選んだ人・全員にまとめて操作する（計算・確認依頼・公開）。
- 1人だけ止めたい場合は「保留」にして理由を残す。他の人の処理は止めない。
- 行を開くと、その1人の詳細と個別修正ができる。修正後は一覧に戻る。
- 一部が失敗しても全体を巻き戻さない。失敗した人だけを一覧に残し、「失敗した人だけ再実行」できるようにする。

### 個人型をまとめて始める

4月の新卒一斉入社などのため、個人型の手続きを一括で開始できるようにする。

1. CSV取込（または招待の一括送信）で、1人1件の手続きを一括作成する。
2. 共通のステップ（雇用条件の確認依頼、資格取得届の作成、承認、提出）は、「同じステップにいる人」をまとめて一括操作する。
3. 例外がある人だけ、個人の画面で対応する。
4. 資格取得届は複数人を1つのPDFにまとめ、ZIPでまとめてダウンロードできるようにする。

### 規模への技術的な備え

- 一覧はすべてページングと絞り込みにする（現状は給与一覧の既定20名、算定一覧の100名、定例業務の1回100名に上限がある）。
- 数百名を超える処理はバックグラウンドジョブにし、進捗バーで表示する。画面を閉じても処理は続き、完了したら通知する。
- 同じ操作の二重実行を防ぐ（操作IDによる制御は定例業務で実装済み。他の一括処理にも広げる）。
- 千人規模のテストデータで、一覧表示と一括計算の所要時間を確認する。

## UIの統一

- 色・余白・文字サイズを `styles.scss` のデザイントークン（CSS変数）に集約し、インラインstyleを撤去する。
- 状態の色を4種に統一する：要対応＝赤、あなたの番＝青、他の人の待ち＝灰、完了＝緑。
- 読み込み中・データなし・エラーの表示を共通コンポーネントにする。
- 主ボタンは1画面に1つだけ。
- ログイン画面のラベル崩れとタブ名を直す。

## 実装順（縦に1本ずつ）

1. 共通部品：ウィザードの枠（進捗バー・ステップ一覧・説明・戻る／次へ）、状態色、用語集。
2. **入社手続きを一本道で完成させる**（本人入力の確認 → 台帳登録 → 雇用条件 → 承認依頼 → 加入判定・等級 → 資格取得届 → 提出）。
3. ホームのやることリスト。
4. 退職・扶養・休業へ展開。
5. 毎月の処理。
6. 算定基礎届・賞与・随時改定。
7. サイドバーの整理と、旧画面（`/salary` 等）への直接導線の撤去。

各段階の完了条件：労務初心者が説明書なしで、ホームから手続きを完了まで進められること（実ブラウザーで確認）。
