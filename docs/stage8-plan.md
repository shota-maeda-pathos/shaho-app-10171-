# 段階8（セキュリティ）の方針

2026-10-31 作成、同日ユーザー承認。終わりの条件（roadmap）：カタログ14章のチェックリストが埋まる。

## 前提として分かったこと

- 個人番号：本番では今どこにも保存されていない。読み書きの関数（`employeeSecretsGet`・`employeeSecretsUpdate`）は平文のままで未公開。従業員の画面の「マイナンバー」欄は保存しても捨てられている。
- ログインはメールとパスワードだけで、画面から Firebase に直接ログインしている（`core/services/auth.service.ts`）。ロック・セッションの時間切れはない。
- 監査ログは更新の操作だけ（ログイン・PDF出力・検索・CSVは残していない）。
- **Authentication は task-app と共通**（kensyu10171）。ログイン方法の設定・パスワードのポリシー設定・ブロッキング関数は task-app のログインにも効くので使わない（Google の有効化だけは task-app の画面に出さないので影響しない）。

## 決めたこと（2026-10-31 ユーザー承認）

| # | 項目 | 決定 |
|---|---|---|
| 1 | 個人番号の暗号化の鍵 | **Cloud KMS**（東京に鍵を作る）。関数だけが鍵を使え、Firestore には暗号文だけを置く。費用は月数十円程度 |
| 2 | 個人番号を見るとき | ふだんは**全桁を伏せる**（「●●●● ●●●● ●●●●」。カタログどおり）。理由を選んでから（届出の作成・本人確認など）12桁を1回だけ表示し、専用の閲覧ログ（誰が・いつ・誰の・理由）を残す。個人番号での検索はせず、CSVに個人番号を出さない |
| 3 | Googleログイン | Authentication で Google を有効にし、ログイン後に**サーバーで会社の許可ドメインと招待を確かめる**。許可ドメインが未設定なら招待された人はどの Google アカウントでも可（カタログどおり）。ブロッキング関数は使わない |
| 4 | ログインの作り方・5回失敗でロック | **サーバー経由のログイン**：画面はパスワード（または Google のトークン）を関数に送り、関数が確かめて失敗を数え、通ればセッション番号つきのトークン（カスタムトークン）を渡す。サーバーの認証はセッション番号のないトークンを拒む（Firebase に直接ログインしても何もできない）。5回失敗で30分ロック、管理者が解除できる。関数の実行アカウントにトークンを作る権限を足す（Google Cloud の設定の変更） |
| 5 | セッション | 無操作30分・ログインから8時間で自動ログアウト。画面の時計に加え、サーバーもセッションの開始と最後の操作の時刻で拒む |
| 6 | 監査ログの拡充 | ログイン（成功・失敗）・ログアウト・PDF出力・個人番号の閲覧・CSV出力・検索を追加し、IPと氏名を残す。前の記録の指紋を持たせて改ざんを見つけられるようにする。5年の保存は消さないことで満たす |
| 7 | パスワードのポリシー | 8文字以上・英字と数字の混在・前に使ったものは不可。アプリの変更画面とログインの関数で確かめる。メールでのリセットは Firebase 標準の画面で行うため、リセット後の最初のログインで関数が使い回し・弱いパスワードに気づき、変更をお願いする画面を出す |
| 8 | 端末一覧と切断 | 本人がログイン中の端末（ブラウザー・IP・ログイン時刻・最後の操作）を見て、切断できる（#4 のセッション番号で行う） |
| 9 | レート制限 | 利用者ごとに1分あたりの呼び出し回数に上限を設ける |
| 10 | 監査ログの画面 | 管理者だけ。期間・操作者・種類で絞り込み、CSVで出力する |

## 進め方

1. 個人番号（#1・#2）：KMS の鍵を作る（設定の変更。事前に確認）→ 関数を暗号化に直して公開 → 従業員の画面に表示・入力・閲覧理由 → 閲覧ログ。
2. ログイン（#4・#5・#7・#8）：サーバー経由のログインとロック → セッション・端末一覧 → パスワードのポリシー → Googleログインと許可ドメイン（#3。Authentication の設定変更は事前に確認）。
3. 監査ログ（#6・#10）とレート制限（#9）、認証の変更を全関数に反映する再デプロイ（未公開の7個は除く）。
4. 14章のチェックリストを埋める。全ロールでの一周は段階10。

## 本番への影響と確認すること

- KMS の API を有効にし、鍵を作り、関数の実行アカウントに鍵を使う権限を与える（Google Cloud の設定の変更）。
- 関数の実行アカウントにトークンを作る権限を与える（同上）。
- Authentication で Google を有効にする（task-app と共通の設定）。
- 関数のデプロイ（新しい関数と、認証を直した全関数の再デプロイ）。
- サーバー経由のログインに切り替えた関数から順に、Firebase への直接ログインのトークンは拒まれる。画面の切り替えと関数のデプロイをそろえる。
- いずれも実行の前にユーザーに確認する。
