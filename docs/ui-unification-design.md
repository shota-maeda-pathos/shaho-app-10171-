# UI統一（段階7.5）の設計

2026-10-30 にユーザーと決めた内容。叩き台と比較の画面は `ui-proposals/`（`index.html` が考え方、`decide-*.html` が比較）。実装は段階7のあと・段階8の前に行う。

## 1. 骨組み（全手続き共通）

どの手続きの画面も、上から次の順に並べる。1人の手続きも多人数の手続きも同じ。違うのは本体だけ。

1. **見出し**：種類のタグ・件名・期限や対象人数。右に補助のボタン（CSV取込・履歴など）
2. **横並びのステップ**：1本だけ。ステップを押すとそのステップの本体に切り替わる
3. **本体**：多人数＝対象者の表、1人＝入力欄。本体の上に「やること」の1行
4. **下に固定の操作バー**：選択中の人数／保存の状態、注意の1行、主ボタン

- 主ボタンは1画面に1つ。いつも操作バーの右端。
- 集計のカードは別に作らない。数字はステップと絞り込みのチップに入れる。
- 見本：`ui-proposals/bonus.html`（多人数）、`ui-proposals/onboarding-person.html`（1人）

## 2. 説明の出し方（比較C）

- 「やること」は本体の見出しの横に1行だけ。
- 「次に起こること」は主ボタンの文言で伝える（例：「台帳に登録して雇用条件へ →」「承認を依頼する（6名） →」）。
- 「なぜ必要か」の常設の枠と「詳しく」はやめる。理由は、押す前に知っておくべき場面だけ、操作バーの主ボタンの横に注意の1行として出す。対象：
  - 取り返しのつかない操作（承認依頼・承認・提出・取り消し）
  - 期限の超過・間近
  - 法律上の決まりで迷いやすい所（上限・免除・遅延理由が要るなど）
- 用語の意味は今ある用語集（`app-term`）の ⓘ に任せる。
- 今の `what`／`why`／`next` の文章は、`what` を1行に縮めて使う。`why` は注意の文言の材料にし、それ以外は消す。

## 3. 1人ずつの手続きの一覧（比較A）

- **入社・退職・年齢到達**は「日ごと×事業所」のまとめとして扱う。見た目は賞与と同じ（ステップ＋対象者の表＋操作バー）。
  - 入社＝入社日ごと、退職＝退職日ごと、年齢到達＝到達月ごと。
  - 同じ日（月）の人を追加すると、自動で同じまとめに入る。
  - ステップの数字は人数の内訳（例：「2名 あなたの番・1名 本人待ち」）。ステップを押すと、そのステップにいる人に表を絞り込む。
  - 表の行に、その人の小さな進み具合（ミニステップ）を出す。
  - 行を押すと1人の画面（同じ骨組み）に移る。
  - **1名だけのまとめでも、まとめの画面を通る**（一貫性を優先）。
  - まとめて本人に入力を依頼・まとめて承認依頼ができる。
- 扶養・産休育休・雇用条件の変更・異動など時期がばらばらな手続きは、まとめを作らず、手続き一覧から1人の画面を開く。
- 見本：`ui-proposals/decide-person-list.html` の案A

## 4. 1人分の内訳（比較A）

- 多人数の表で名前を押すと、右からパネルが重なって開く。表の幅と絞り込みはそのまま。
- パネルには「‹ 前」「次 ›」と「2 / 8人目」。Escで閉じる。
- 使い分け：見る・少し直す（保留・金額の修正）＝パネル、しっかり入力する（入社の本人情報など）＝1人の画面に移る。
- 承認の画面だけは左右に分割した受信箱の形（`ui-proposals/approvals.html`）。
- 見本：`ui-proposals/bonus.html` で名前を押す

## 5. 細かい決まり

| 項目 | 決めたこと |
|---|---|
| 確認 | 承認依頼・提出など取り返しのつかない操作は、画面内の確認ダイアログ（対象の人数・中身の要約・注意を1枚に）。`window.confirm` は使わない。既存の `shared/confirm-dialog` を土台にする |
| 保存 | 1人の画面の入力は自動で下書き保存し、操作バーに「保存済み 10:42」。主ボタンで確定して次のステップへ |
| 状態 | 5種にそろえる：あなたの番（ブランド色）／要確認（橙）／待ち（灰。本人待ち・承認待ちなど誰を待つかは文字で）／完了（緑）／エラー・期限切れ（赤）。今の `StatusTone`（action・yours・waiting・done）を広げる |
| ステップの数字 | 1つだけ出す。優先順：要確認があれば「要確認1名」→ 進行中は「残り3名」→ 全員済みは「完了」→ 未着手は「—」 |
| ホームと手続き一覧 | ホーム＝自分が動くものだけを期限順に。手続き一覧＝待ちも含めた全件。どちらからも同じ手続きの画面へ |
| 画面の幅 | PC中心。スマホではサイドバーを畳み、表は横スクロールで見られる程度。本人ポータル（段階9）だけスマホ優先 |
| 配色・ロゴ | **2026-10-31 ユーザー決定：名前は Ordia、色は Slate blue（#53749B）で確定**。ロゴは3本線のマーク（`shared/ui/logo.ts`）、色と文字は `styles.scss` の `--app-brand-*`（Material の色も上書き）。タブ名・ログイン・ポータル・ファビコン（`public/favicon.svg`）も Ordia |
| サイドバー | **2026-10-31 ユーザー決定：提案どおり**。ホーム・手続き・承認・届出・従業員＋「管理」（集計・試算・用語集・事業所・設定）。手続きを始める・毎月の処理・賞与・算定・各手続きは「手続き」の中として選択表示。上に事業所の切替、下に自分の名前（押すとポータル・ログアウト）。上部バーはパンくずと検索（Ctrl+K。手続き一覧の `?q=` に渡す）。960px 未満はアイコンだけに畳む |

## 6. 実装の進め方（案）

1. 共通部品の中身を変える：`shared/ui/wizard.ts`（ステップ・1行の説明・操作バー）、`shared/ui/target-list.ts`（絞り込みチップ・右のパネル）、`shared/ui/status-badge.ts`（5種）、確認ダイアログ。
2. 賞与で多人数の型を、入社で「まとめ＋1人」の型を作り直し、画面で確かめる。
3. 残りの手続き（算定・毎月の処理・随時改定・退職・年齢到達・扶養・休業・雇用条件の変更・異動）に広げる。
4. ホーム・手続き一覧・承認・届出をそろえる。

入社・退職・年齢到達の「まとめ」をデータとして持つか、表示するときに日付で束ねるかは、着手時に調べて決める。
